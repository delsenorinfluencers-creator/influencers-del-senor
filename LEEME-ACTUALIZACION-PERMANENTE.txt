ACTUALIZACIÓN — JÓVENES INFLUENCERS DEL SEÑOR
==============================================

ESTA ENTREGA
- Contiene el proyecto recibido V45 y conserva el archivo local logo-influencers-del-senor.png.
- Incluye los scripts SQL que ya venían en el proyecto.
- Este ZIP no puede recuperar por sí solo registros borrados de Supabase ni publicar cambios en el servidor.

ANTES DE PUBLICAR (IMPORTANTE)
1. Haz una copia de seguridad del proyecto actual del hosting/repositorio.
2. En Supabase, crea una copia de seguridad/exporta las tablas con noticias, historical_64 (64 Datos), programas, editoriales, configuración y demás contenidos. Si el plan no permite backup automático, exporta las tablas desde Table Editor/CSV y guarda el esquema SQL.
3. NO ejecutes supabase.sql ni supabase-completo.sql sobre una base de datos existente sin revisar su contenido: un script de instalación puede cambiar el esquema y no es una herramienta para recuperar datos perdidos.
4. Publica los archivos del proyecto en el MISMO proyecto de hosting (por ejemplo, el mismo proyecto de Vercel y repositorio), no crees otro proyecto por error.
5. Mantén config.js con la URL y la clave pública/anon de Supabase correctas. Nunca publiques una service_role o clave secreta.
6. Tras publicar, prueba inicio, logo, inicio de sesión de administrador, creación/edición de una noticia, 64 Datos y páginas individuales. Verifica que los cambios sigan al recargar y desde otro navegador.

PARA MANTENER CAMBIOS PERMANENTES
- El logo está en /logo-influencers-del-senor.png. Debe subirse junto con el resto de los archivos.
- El código debe versionarse en Git (commit antes de cada actualización) y desplegarse desde ese repositorio.
- Las noticias y contenidos dinámicos deben guardarse en Supabase mediante el panel; no basta con guardarlos en el navegador.
- Configura copias de seguridad periódicas de Supabase y conserva una copia externa.
- No reemplaces la base de datos con una base vacía para “actualizar” el diseño.

NOTA SOBRE 64 DATOS
El ZIP recibido contiene 64-datos/index.html y supabase-fix-64-datos-uuid.sql. No contiene una página independiente dato.html ni una regla de reescritura .htaccess. Por eso, esta entrega no garantiza que las URL del tipo /64-datos/dato/mi-slug funcionen en el hosting actual. La configuración de rutas depende del proveedor/hosting y debe comprobarse en el proyecto publicado.

PUBLICACIÓN EN VERCEL (si ese es el hosting usado)
1. Descarga y descomprime el ZIP.
2. Sube el contenido de la carpeta influencers-del-senor al mismo repositorio Git conectado a Vercel.
3. Revisa el diff y confirma que no se hayan eliminado archivos actuales más nuevos.
4. Haz commit y push; espera a que termine el deployment.
5. Prueba el sitio y conserva el deployment anterior para poder volver atrás.

Este paquete es una copia de los archivos recibidos con instrucciones de preservación; no se ha conectado al hosting ni a Supabase, por lo que no se afirma que ya esté publicado ni que los datos perdidos hayan sido restaurados.
